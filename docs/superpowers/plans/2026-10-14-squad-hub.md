# Squad Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add a shared Squad Hub where each manager arranges their drafted roster into an editable 4-3-3 with a bench panel.

**Architecture:** Keep roster and lineup rules in a pure `src/squad-core.mjs` module. Add a new app view in `src/app.mjs` and styles in `styles.css`; persist lineup changes through the existing shared state, leaving current league and draft records intact.

**Tech Stack:** Vanilla JavaScript ES modules, Node.js built-in test runner, HTML templates, CSS, existing JSON shared-state API.

**Spec:** `docs/superpowers/specs/2026-10-14-squad-hub-calendar-design.md` (Squad Hub section only; calendar receives its own plan after this increment).

## Global Constraints

- Keep existing draft, transfer, shared-state, and match flows working.
- No new database or paid dependency.
- Add optional `league.squads`; existing states without it must remain valid.
- Do not add login or accounts.
- Do not reset or replace existing league, draft picks, transfers, or logs.
- Keep the separate calendar feature out of this increment.
- Do not commit or push before the user reviews and approves changes.

## Review Focus

- A drafted player transferred to another team must show in the new squad only; test team roster derivation from current pick ownership.
- A player cannot be assigned to two starter slots; test that moving a starter clears or swaps its old slot.
- An unknown player ID must not be added to a lineup; test rejection and unchanged league state.
- A human manager cannot edit another human team's lineup; test both permitted and denied manager ownership.
- A team with fewer than eleven rostered players must render/retain empty slots without creating players; test empty slots and bench roster.

### Task 1: Squad roster and lineup domain rules

**Files:**
- Create: `src/squad-core.mjs`
- Create: `tests/squad-core.test.mjs`

**Interfaces:**
- `SQUAD_SLOTS` is the ordered array of `{ id, label, x, y }` 4-3-3 pitch slot descriptors; IDs are exactly `GK`, `LB`, `LCB`, `RCB`, `RB`, `LCM`, `DM`, `RCM`, `LW`, `ST`, `RW`.
- `isLeagueHost(league, managerTeamId)` returns true only for the first human team in the league, which is the host team established by `startLeague`.
- `getTeamRoster(league, teamId, playerPool = [])` returns current picks owned by `teamId`, enriched from `playerPool` where the pick lacks position or other display metadata. Current `draft.picks` ownership is authoritative, so transfers are naturally reflected.
- `getTeamSquad(league, teamId)` returns `{ formation: '4-3-3', starters: { GK, LB, LCB, RCB, RB, LCM, DM, RCM, LW, ST, RW } }`, using empty strings for unfilled slots when no saved lineup exists.
- `setStartingPlayer(league, teamId, slotId, playerId, managerTeamId)` returns `{ league, error? }`. It validates the slot, membership, uniqueness, and ownership. The acting manager may edit their own team; the manager whose name matches `league.adminName` may also edit CPU teams. Assigning an existing starter to another slot moves it, assigning a bench player to an occupied slot sends the displaced starter to the bench, and `playerId === ''` clears the slot.
